# 中文禁語庫

一份「中國用語 → 台灣慣用語」對照表，供寫作與審稿時比對。

## 內容

| 檔案 | 說明 | 筆數 |
|---|---|---|
| `terms.tsv` | 收錄的禁語與建議替代用語 | 117 |
| `rejected.tsv` | 審過但判定不收的詞 | 22 |
| `verification.tsv` | 依據欄的佐證網址 | 38 |

三份都是 **tab 分隔（TSV）**，欄位如下：

```
terms.tsv         禁語 → 建議用語 → 類別 → 依據 → 收錄日期
rejected.tsv      詞 → 不收錄原因 → 判定日期
verification.tsv  禁語 → 建議用語 → 來源類型 → 查到的詞條 → 來源網址 → 備註 → 查證日期
```

`類別` 共八種：資訊科技、網路社群、飲食、交通、商業管理、公共事務、醫療、日常生活。

## 依據欄的可信度

`依據` 欄只有五種值，語意嚴格區分「查得到」與「查不到」：

| 依據 | 筆數 | 意義 | 須附網址 |
|---|---:|---|---|
| `待查證` | 72 | **本輪未找到書面來源**，狀態是未知 | 否 |
| `國教院樂詞網` | 29 | 樂詞網實際查得到詞條 | 是 |
| `兩岸用語對照` | 8 | 兩岸用詞差異參考資料佐證，非辭典本文 | 是 |
| `語感重構` | 7 | 黨政／管理腔，理由是語感而非辭典明文 | 否 |
| `主管機關用語` | 1 | 主管機關官網用字 | 是 |

宣稱有具體來源的 38 筆，全部在 `verification.tsv` 附了 `https://` 網址與查到的詞條，
lint 會交叉比對來源類型與建議用語。

**`待查證` 的 72 筆代表「這一輪沒查到」，不是「業界慣用」。** 未知就標未知——
「沒找到書面依據」推不出「台灣業界穩定使用」。`業界慣用` 保留給拿得出語料或
業界文件的情形，同樣需要附網址。

樂詞網的佐證網址採搜尋形式（`/search/?query_term=...`）而非 `/detail/<id>/`，
因為後者會轉回首頁，無法帶審查者回到個別詞條。

## 驗證

```bash
python3 scripts/lint.py
```

通過時輸出：

```
四項檢查全數通過｜禁語 117 筆、已排除詞 22 筆
```

四項檢查為：格式（tab 分隔與欄位數）、必填欄位、重複與交集、內容一致性。CI 會在每次 push 與 PR 時執行。

lint 本身的回歸測試：

```bash
python3 -m unittest discover -s tests -v
```

共 31 項，涵蓋每種檢查的失敗案例與行號正確性，同樣在 CI 執行——用意是防止日後修改 lint 時把檢查改鬆而沒被發現。

## 加詞

收詞規則寫在 [`CLAUDE.md`](CLAUDE.md)，包含查證來源的優先順序、該收與不該收的判準、依據欄的填法、防重複的 grep 指令。修改資料前請先讀。

## 注意

三個 TSV 都必須使用真正的 tab（U+0009）。複製貼上時 tab 常被編輯器轉成空白，lint 會擋下來並提示「疑似 tab 被轉成空白」——那是格式問題，修分隔符即可，不要放寬 `scripts/lint.py` 的規則。

三層防護的實際分工：

| 層 | 機制 | 能擋什麼 |
|---|---|---|
| Git | `.gitattributes` `text eol=lf` | 跨平台 checkout 時 LF 被轉為 CRLF |
| 編輯器 | `.editorconfig` `indent_style = tab` | 提示以 hard tab 縮排 |
| 提交前後 | `scripts/lint.py` + CI | 分隔符、欄位、內容的實際驗證 |

`.editorconfig` 規範的是**縮排**，並不保證保留 TSV 欄位中間的分隔符，EditorConfig 也沒有可攜的屬性能做到這件事。**分隔符完整性只由 lint 與 CI 強制驗證。**
